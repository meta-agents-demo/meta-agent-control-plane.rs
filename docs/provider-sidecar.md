# Provider-neutral Rust client and sidecar

The control plane never embeds OpenAI, Anthropic, or Google SDKs. Provider runtimes submit concise observable lifecycle updates, which are normalized into the canonical event protocol before transport.

This integration is for API-backed or otherwise programmable agents. It does **not** claim that the ChatGPT consumer product exposes a direct daemon connection. ChatGPT product automation requires an explicit external integration that produces the documented OpenAI observation shape.

## Security and privacy boundary

The sidecar accepts one provider observation JSON object per input line and:

- rejects nested keys such as `chain_of_thought`, `hidden_reasoning`, `reasoning_content`, and `scratchpad`;
- never adds provider API keys or the control-plane token to an event;
- never prints the configured control-plane token;
- reports line numbers and bounded error classes without echoing the rejected payload;
- validates the canonical event before opening a transport;
- rejects command/control event kinds locally when UDP is selected.

`META_AGENT_TOKEN` is sent as an HTTP/WebSocket bearer header or as the existing TCP/UDP transport-frame token. Query-string credentials are intentionally not generated by the Rust client.

## Sidecar usage

Run the local daemon with authentication:

```bash
export META_AGENT_AUTH_TOKEN='replace-with-at-least-16-bytes'
export META_AGENT_PROTECT_READ_API=true
cargo run --bin meta-agent-control-plane
```

Normalize an OpenAI-style observable update without networking:

```bash
cargo run --bin meta-agent-sidecar -- \
  --provider openai \
  --dry-run \
  < fixtures/providers/openai-progress.json
```

Forward Anthropic observations over HTTP:

```bash
export META_AGENT_TOKEN="$META_AGENT_AUTH_TOKEN"
cargo run --bin meta-agent-sidecar -- \
  --provider anthropic \
  --transport http \
  --endpoint http://127.0.0.1:8787/api/v1/events \
  < fixtures/providers/anthropic-reflection.json
```

Forward Gemini observations over the authenticated agent WebSocket:

```bash
cargo run --bin meta-agent-sidecar -- \
  --provider gemini \
  --transport websocket \
  --endpoint ws://127.0.0.1:8787/ws/agent \
  < fixtures/providers/gemini-completion.json
```

TCP and UDP endpoints are socket addresses rather than URLs:

```bash
cargo run --bin meta-agent-sidecar -- \
  --provider openai \
  --transport tcp \
  --endpoint 127.0.0.1:8788 \
  < fixtures/providers/openai-progress.json
```

UDP remains telemetry-only. Completion, registration, goal declaration, and task declaration observations fail locally rather than being transmitted.

## Embedded Rust client

```rust,no_run
use std::time::Duration;

use meta_agent_control_plane::{
    client::{ClientConfig, ClientTransport, EventClient},
    provider::normalize_openai,
};

# async fn example() -> Result<(), Box<dyn std::error::Error>> {
let event = normalize_openai(serde_json::from_str(include_str!(
    "../fixtures/providers/openai-progress.json"
))?)?;
let client = EventClient::new(
    ClientConfig::new(
        ClientTransport::Http {
            endpoint: "http://127.0.0.1:8787/api/v1/events".to_owned(),
        },
        Some("replace-with-at-least-16-bytes".to_owned()),
    )
    .with_timeout(Duration::from_secs(5)),
)?;
let acknowledgement = client.send(&event).await?;
assert_eq!(acknowledgement.event_id, event.event_id);
# Ok(())
# }
```

The embedded HTTP and WebSocket clients deliberately accept only `http://` and `ws://`. For remote operation, place the sidecar next to the agent runtime and use a local TLS terminator, service mesh, SSH tunnel, or private overlay network. This prevents the small client from pretending to provide TLS validation that it does not implement.

## Deterministic mock demo

With the daemon running:

```bash
export META_AGENT_TOKEN="$META_AGENT_AUTH_TOKEN"
cargo run --example mock_provider_parallel
```

The demo normalizes checked-in OpenAI, Anthropic, and Gemini fixtures and sends each canonical event through the same Rust client. The fixtures are reused by integration tests and contain no real provider credentials, prompts, or hidden reasoning.

## Test coverage

`tests/client_transports.rs` boots a real daemon on ephemeral loopback ports and proves:

- HTTP, WebSocket, and TCP acknowledgements correspond to the submitted event and expected transport;
- UDP telemetry reaches the same store projection;
- UDP command/control events are rejected before network mutation;
- wrong HTTP credentials return a bounded structured error.

`tests/sidecar_cli.rs` executes the real sidecar binary against deterministic fixtures and proves provider normalization plus hidden-reasoning rejection without network access.
